# ISO 15118-2 DC State Machine

## Overview

ISO 15118-2 defines the communication protocol between an EV (EVCC) and a charger (SECC) for AC and DC charging. In EVerest, the SECC side is implemented by Josev — a Python stack maintained by Switch EV and the Linux Foundation.

The state machine is located at:
`everest-core/build/dist/libexec/everest/3rd_party/josev/iso15118/secc/states/iso15118_2_states.py`

## Full DC Charging Sequence

    SDP (Service Discovery Protocol)
            ↓
        SupportedAppProtocol
            ↓
        SessionSetup
            ↓
        ChargeParameterDiscovery
            ↓
        CableCheck
            ↓
        PreCharge
            ↓
        PowerDelivery (Start)
            ↓
        CurrentDemand ←── main charging loop
            ↓
        PowerDelivery (Stop)
            ↓
        WeldingDetection
            ↓
        SessionStop

## State Details

### SDP — Service Discovery Protocol
Network layer — not an ISO 15118 state but a prerequisite. The EV sends a UDP multicast packet over IPv6 link-local (`fe80::`) announcing its presence. The charger responds with its IP address and port.

**Critical:** SDP requires an IPv6 link-local address on the network interface. This fails on WSL2 — native Linux required.

### SupportedAppProtocol
The EV sends a list of supported protocols with priorities. The charger selects the first match:
1. ISO 15118-2
2. DIN 70121
3. ISO 15118-20

The selected protocol determines which state machine runs for the rest of the session.

### SessionSetup
- Extracts and publishes the EVCC ID (EV MAC address)
- Manages session ID — new session or resumed session
- Resets EVSE values for the new session

Sessions can be **resumed**: if the cable disconnects briefly, the EV can reconnect with the same session ID and continue without re-authenticating.

### ChargeParameterDiscovery
The EV declares the requested energy transfer mode (e.g. `DC_extended`, `DC_BPT`). The charger validates it supports that mode. Can repeat in a polling loop if the charger responds with `EVSEProcessing=Ongoing`.

### CableCheck
Safety-critical state. The charger activates the IMD (Isolation Monitoring Device) to measure the cable's isolation resistance before applying high voltage.

- `VALID` or `WARNING` → proceed to PreCharge
- `FAULT` or `NO_IMD` → session terminated, no voltage applied

Repeats in a polling loop until the IMD finishes.

### PreCharge
The charger ramps its DC output voltage to match the EV battery voltage. The EV continuously sends its target voltage. The charger adjusts until the difference is less than 20V (IEC 61851-23 requirement). Only then can the DC contactor close safely — closing with a larger difference would cause an arc and damage both the contactor and the battery.

### PowerDelivery
Used both to **start** and **stop** the energy flow. The `ChargeProgress` field determines the action:
- `Start` → transition to CurrentDemand
- `Stop` → transition to WeldingDetection
- `Renegotiate` → return to ChargeParameterDiscovery without stopping the session

### CurrentDemand — Main Charging Loop
The core of DC charging. The EV continuously sends `CurrentDemandReq` with:
- Target voltage and current
- Maximum limits (current, voltage, power)
- SOC and status
- Estimated time to bulk/full charge

The charger responds with present voltage and current. This is a closed-loop control — the charger adjusts output every cycle based on what the EV requests.

Published via MQTT on every cycle:
- `dc_ev_target_voltage_current`
- `dc_ev_status` (SOC, ready, error code)
- `dc_ev_maximum_limits`
- `dc_ev_remaining_time`

### WeldingDetection
After stopping, the charger measures its output voltage. If the DC contactor welded shut (a physical defect from electrical arcing), the voltage will remain high instead of dropping to zero. The EV detects this and reports it.

### SessionStop
Two modes:
- `TERMINATE` — session closed permanently, context cleared
- `PAUSE` — session suspended, session ID preserved for resumption

Pause enables smart charging use cases: the grid operator can pause charging when energy is expensive and resume when it is cheap, without requiring re-authentication.
